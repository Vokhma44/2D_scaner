# Протокол обмена «телефон ↔ агент»

Версия протокола: **1** (`PROTOCOL_VERSION`). Транспорт — HTTPS и WebSocket
поверх того же порта. Все сообщения — JSON в UTF-8, тип сообщения лежит в поле
`type`.

Реализации: `agent/src/main/kotlin/ru/ruznak/netscan/protocol/Messages.kt`
и `mobile/src/types.ts` — при изменении протокола правятся обе.

## 1. Сопряжение

Агент печатает при старте QR-код с адресом вида:

```
https://192.168.1.10:8443/?p=FY6E-2VKV-3QM7
```

Телефон открывает эту страницу, забирает код из параметра `p` и обменивает его
на долгоживущий секрет сессии.

### `POST /api/pair`

```json
{
  "token": "FY6E-2VKV-3QM7",
  "device": { "name": "Склад-1", "platform": "Android", "userAgent": "...", "appVersion": "1.0.0" }
}
```

Ответ `200`:

```json
{
  "deviceId": "iN3iQ78WFacG",
  "sessionToken": "gH1v...",
  "serverVersion": "1.0.0",
  "protocolVersion": 1,
  "status": "active",
  "settings": { "duplicateWindowMs": 1500, "allowedFormats": [], "hostName": "PC-SKLAD" }
}
```

| Код | Когда |
| --- | --- |
| `403 invalid_token` | код сопряжения неверен или истёк |
| `429 rate_limited` | превышен лимит попыток с одного адреса |
| `400 bad_request` | тело запроса не разобрано |

`status: "pending"` означает, что на ПК включено подтверждение устройств:
сканировать можно только после нажатия «Подтвердить» в веб-консоли.

Код сопряжения нечувствителен к регистру и дефисам — его можно ввести руками.
Секрет сессии телефон хранит в `localStorage`; на ПК от него остаётся только
SHA-256.

### `GET /api/session`

Заголовок `Authorization: Bearer <sessionToken>`. Отвечает `200` с описанием
устройства или `401`, если сессия отозвана. Используется телефоном при запуске,
чтобы понять, нужно ли сопрягаться заново.

### `GET /api/health`

Без авторизации, для проверки доступности:

```json
{ "app": "netscan", "version": "1.0.0", "protocolVersion": 1, "host": "PC-SKLAD", "devicesOnline": 2 }
```

## 2. Канал сканов

```
wss://192.168.1.10:8443/api/ws?s=<sessionToken>
```

Секрет передаётся параметром запроса, потому что браузер не позволяет задать
заголовки при открытии WebSocket. Канал защищён TLS, поэтому секрет не виден в
сети; в журналы агента он не попадает.

Неизвестный или отозванный секрет — закрытие с кодом `1008`. Телефон в этом
случае не переподключается, а показывает экран сопряжения.

### Телефон → агент

| `type` | Поля | Назначение |
| --- | --- | --- |
| `hello` | `device`, `protocolVersion` | представление после подключения |
| `scan` | `id`, `code`, `format`, `scannedAt`, `source` | один отсканированный код |
| `scans` | `scans: [...]` | пачка сканов (выгрузка офлайн-очереди) |
| `ping` | `ts` | измерение задержки |

```json
{ "type": "scan", "id": "0f3c…", "code": "0104607012345678", "format": "data_matrix", "scannedAt": 1756360000000, "source": "camera" }
```

`source` — `camera`, `manual` (введён руками) или `image`.

**`id` обеспечивает идемпотентность.** Телефон генерирует его один раз на скан
и повторяет при повторной отправке. Агент помнит последние идентификаторы, и
повторная доставка не приводит к двойному вводу на ПК. Это то, что позволяет
безопасно выгружать офлайн-очередь после разрыва связи.

### Агент → телефон

| `type` | Поля | Назначение |
| --- | --- | --- |
| `welcome` | `deviceId`, `serverVersion`, `protocolVersion`, `settings` | ответ на подключение |
| `ack` | `id`, `status`, `detail` | судьба конкретного скана |
| `pong` | `ts`, `serverTs` | ответ на `ping` |
| `notice` | `level`, `text` | сообщение оператору |
| `settings` | `settings` | настройки изменили в консоли на ПК |

Значения `ack.status`:

| Значение | Смысл | Что делает телефон |
| --- | --- | --- |
| `accepted` | код введён на ПК | убирает из очереди, помечает в журнале |
| `duplicate` | повтор в окне подавления или уже обработанный `id` | убирает из очереди |
| `filtered` | не прошёл фильтры (длина, символика, регулярное выражение) | показывает причину |
| `failed` | ошибка вывода на ПК | звук ошибки, код остаётся в журнале |

Скан удаляется из офлайн-очереди **только после `ack`**. Разрыв связи в момент
отправки не теряет код и не вводит его дважды.

## 3. Путь скана внутри агента

```
ack ◀── журнал ◀── приёмники ◀── форматирование ◀── подавление повторов ◀── фильтры ◀── scan
```

1. **Фильтры** — длина, белый список символик, регулярное выражение.
2. **Подавление повторов** — по паре «устройство + код» в окне
   `scan.duplicateWindowMs` и по идентификатору скана.
3. **Форматирование** — префикс, суффикс, необязательная замена разделителя GS1, удаление
   управляющих символов (табуляция сохраняется).
4. **Приёмники** — клавиатура, буфер обмена, консоль, файл, вебхук. Ошибка
   одного приёмника не отменяет остальные, но возвращается телефону в `ack`.

Шаги 2–4 выполняются под одним замком: два телефона, сканирующие одновременно,
не могут перемешать символы в одном окне.

## 4. Формат вебхука

```json
{
  "code": "0104607012345678",
  "raw": "0104607012345678",
  "format": "data_matrix",
  "deviceId": "iN3iQ78WFacG",
  "deviceName": "Склад-1",
  "scanId": "0f3c…",
  "receivedAt": "2026-08-28T06:20:36Z"
}
```

`code` — то, что ушло бы в клавиатуру (с префиксом и текстовым суффиксом),
`raw` — исходное содержимое кода. Ответ вне диапазона 2xx возвращается телефону
как `ack.failed`.

## 5. API веб-консоли

Доступно только с самого ПК. Изменяющие запросы дополнительно проверяют `Origin`
локальной HTTPS-консоли для защиты от CSRF.

| Метод и путь | Назначение |
| --- | --- |
| `GET /api/console/state` | полное состояние: QR, устройства, журнал, статистика, настройки |
| `GET /api/console/qr.svg` | QR сопряжения в SVG |
| `POST /api/console/config` | сохранить настройки; в ответе `restartRequired` для сетевых параметров |
| `POST /api/console/pairing/rotate` | выпустить новый код сопряжения |
| `POST /api/console/devices/{id}/{approve\|revoke\|forget}` | управление устройствами |
| `POST /api/console/test` | отправить код на ввод, не доставая телефон |
| `POST /api/console/history/clear` | очистить журнал |

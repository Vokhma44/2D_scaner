# Безопасность

Агент умеет вводить текст в активное окно ПК. Это мощная возможность, поэтому
доступ к нему нужно ограничивать так же аккуратно, как доступ к самой машине.

## Модель угроз

Агент рассчитан на доверенную локальную сеть: офис, склад, домашний Wi-Fi.
В этой сети он защищается от следующего:

| Угроза | Защита |
| --- | --- |
| Посторонний в той же сети нашёл открытый порт и шлёт коды | Обязательное сопряжение по коду, секрет сессии у каждого устройства |
| Перебор кода сопряжения | Ограничение попыток с одного адреса (по умолчанию 10 в минуту) |
| Перехват кодов в сети (открытый Wi-Fi) | Весь трафик, включая WebSocket, идёт по TLS |
| Утерянный или уволившийся телефон | Отзыв устройства в консоли, ротация кода сопряжения |
| Чужой ПК в сети открывает консоль и меняет настройки ввода | Консоль доступна только с localhost |
| Кража секретов из файлов агента | Секреты сессий хранятся как SHA-256, ключ TLS — с правами только для владельца |

Чего агент **не** делает: он не рассчитан на публикацию в интернет. Не
пробрасывайте его порт наружу. Если удалённый доступ нужен, заводите VPN.

## Сопряжение

Код сопряжения — 12 символов из алфавита без похожих знаков (`0/O`, `1/I/l`),
это примерно 60 бит. Он лежит в `~/.netscan/pairing.txt` и переживает
перезапуск: распечатанный QR-код продолжает работать.

- `security.pairingTokenTtlMinutes` — срок жизни кода, `0` — бессрочно;
- `security.pairingAttemptsPerMinute` — лимит попыток с одного адреса;
- `security.requireDeviceApproval` — новое устройство сначала попадает в
  «ожидает подтверждения» и не может сканировать, пока его не подтвердят на ПК;
- `netscan --reset-pairing` — выпустить новый код и отозвать все сессии.

Успешное сопряжение сбрасывает счётчик попыток, поэтому лимит не мешает
подключать телефоны один за другим.

Секрет сессии — 32 случайных байта. Телефон хранит его в `localStorage`, агент —
только хеш SHA-256 в `~/.netscan/devices.json`. Восстановить секрет из файла
нельзя, поэтому его утечка не даёт доступа.

## TLS и предупреждение браузера

Камера в браузере работает только в защищённом контексте. Для адреса
`192.168.1.10` публичный сертификат получить негде, поэтому агент выпускает
самоподписанный: RSA-2048, срок 10 лет, в SAN — `localhost`, имя машины и
адреса всех сетевых интерфейсов. Ключ лежит в `~/.netscan/keystore.p12` с
правами только для владельца.

При первом заходе телефон покажет предупреждение — это нормально для
самоподписанного сертификата. Отпечаток SHA-256 печатается при старте агента и
виден в веб-консоли: сверьте его, прежде чем подтверждать переход.

Убрать предупреждение совсем можно двумя способами:

1. **Установить сертификат агента как доверенный на телефоне.** Экспортируйте
   его и добавьте в хранилище устройства:

   ```bash
   keytool -exportcert -rfc -keystore ~/.netscan/keystore.p12 -storetype PKCS12 \
           -storepass netscan -alias netscan -file netscan.crt
   ```

   Android: Настройки → Безопасность → Шифрование → Установить сертификат.
   iOS: отправьте файл на телефон, установите профиль и включите его в
   Настройки → Основные → Об этом устройстве → Доверие сертификатам.

2. **Выдать агенту нормальный сертификат.** Если у организации есть внутренний
   удостоверяющий центр, положите готовый PKCS#12 на место
   `~/.netscan/keystore.p12` с паролем `netscan` и алиасом `netscan` — агент
   возьмёт его и не станет перевыпускать, пока в SAN есть адреса ПК.

При смене сети (новый Wi-Fi, другой адрес) агент перевыпускает сертификат
автоматически, иначе браузер начал бы ругаться уже на несовпадение имени.

## Веб-консоль

Консоль и её API отвечают только на запросы с самого ПК. Это защищает от
ситуации, когда кто-то из той же сети меняет настройки ввода на чужой машине.

Если агент стоит на неттопе без монитора, откройте доступ явно —
`security.allowRemoteConsole: true` — и ограничьте доступ к порту на уровне
брандмауэра.

## Что стоит сделать при внедрении

1. Включите `requireDeviceApproval` там, где важно контролировать, какие
   телефоны подключаются.
2. Ограничьте порт агента правилом брандмауэра рабочей подсетью.
3. Отзывайте устройства при увольнении сотрудника или потере телефона.
4. Задайте `pairingTokenTtlMinutes`, если код сопряжения показывают на общем
   экране.
5. Проверьте фильтры `scan.filterRegex` и `allowedFormats`: они не только
   удобство, но и защита от ввода постороннего текста в учётную систему.
